# Languages and translation customization

Dash follows Shelf's `i18next` + `i18next-vue` approach: bundled JSON catalogs,
English as the source of truth, a native-name language picker, and a System
preference. It ships English (`en-US`), Japanese (`ja`), Simplified Chinese
(`zh-CN`), Korean (`ko`), and Vietnamese (`vi`).

## Change the interface language

Open **Settings → Language** and choose a language or **Follow system**.
Changes apply without reloading, including navigation, open settings, player
controls, dashboard labels, dates, numbers, and accessibility text. The preference
is stored per browser under `dash.language` and synchronized across tabs on the
same origin. Devices and browser profiles have independent preferences.

System follows the browser's language, including `languagechange` events.
Regional variants map to the shipped language: `ja-JP` → `ja`, `vi-VN` → `vi`,
and Chinese variants → Simplified Chinese, matching Shelf. Unsupported languages
fall back to English. Invalid stored values reset to System. If storage is blocked,
the choice works for the current tab and Settings reports that it cannot persist.

Catalogs ship in the PWA build; switching languages does not fetch a translation
service or contact the driving device. The Go backend, driving gates, and worker
limits are unchanged.

## Customize wording

Edit `frontend/src/i18n/locales/<locale>.json` and rebuild the PWA. The structure matches
Shelf: a feature section with named messages, for example:

```json
{
  "settings": {
    "language": "Language",
    "followSystem": "Follow system"
  }
}
```

English is `en-US.json`. Every shipped catalog must contain the same keys and
interpolation placeholders. For a new message, add a meaningful key to English
and translate it in each other catalog. Use complete phrases, including plurals,
instead of joining translated fragments:

```json
{
  "common": {
    "drives_one": "{{count, number}} drive",
    "drives_other": "{{count, number}} drives"
  }
}
```

In Vue components:

```ts
import { useTranslation } from 'i18next-vue';
const { t } = useTranslation();
// In the template: t('common.drives', { count: drives.length })
```

Use `computed` for translated option arrays or other derived labels; translating
once during setup would freeze their language. Shared TypeScript formatters can
import `t`, `locale`, and `formatNumber` from `frontend/src/i18n`. Those helpers track the
selected locale when used in Vue computed values. Use `Intl` with `locale.value`
for dates, and i18next's `number` formatter for numeric interpolation.

Vue escapes rendered text; translation strings must remain plain text, without
HTML or `v-html`. Keep protocol identifiers, file names, release tags, and stored
option values untranslated. Only their displayed labels change. Camera names
such as `qcamera.ts` identify actual source files. Playback timestamps retain the
precise `m:ss.SSS` notation; manual entry also accepts a decimal comma.

Backend logs and unexpected technical diagnostics retain their original wording
for debugging. Known parked-state, memory/storage, live-support, and update-feed
conditions receive translated explanations. The update error's original detail
remains available under **Technical details**. OSM attribution and map place names
remain source-provided; language changes do not rewrite geographic data.

## Add a language

1. Copy the English catalog into a new BCP-47-named JSON file and translate every
   message, preserving placeholders and the plural key set.
2. Import it and register it in `LOCALES` and `resources` in `frontend/src/i18n/index.ts`.
   Supply its native name as `endonym`.
3. Extend `resolveLocale` if System should map regional tags to it. For a
   language with additional plural categories, add the required forms and update
   the catalog coverage policy. Right-to-left languages also need a direction
   and layout audit; the current five languages are left-to-right.
4. Run the checks below, then build/install using the normal delivery workflow.

There is no translation upload API or device-side catalog override. A customized
PWA is delivered with its matching backend through the existing source-build or
release path, just like other UI changes.

## Verify

```sh
npm test             # Key parity, placeholders, plurals, source coverage, reactivity
make check           # Full project checks and build
# With make serve running against make fixture:
make i18n-smoke       # Five-language desktop/mobile browser flows
```

The browser check covers live switching, reload persistence, cross-tab and System
changes, blocked storage, export dialogs, and mobile viewer/metadata fit. It uses
synthetic recordings and writes screenshots to ignored `.artifacts/`. Chromium
emulation does not replace physical iOS/Android testing or native-speaker review.

Accent selection in Settings uses Shelf’s eight named presets and defaults to blue. It is saved with browser appearance preferences and synchronizes across tabs; localized swatch names live under the `settings.accent*` keys.
